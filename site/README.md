# favseed, in the browser

The third of the three: the [CLI](../bin/favseed.mjs), the [Astro integration](../astro/), and
this. Drop an SVG, get the set, nothing leaves the tab.

```sh
pnpm install && pnpm --filter favseed-site dev   # from the repo root
```

Deployed to <https://favseed.cevdet.ch> by Cloudflare Pages from `main` (settings in
[RELEASING.md](../RELEASING.md)). `trailingSlash: 'never'` with `build.format: 'file'` serves
slash-free URLs without a redirect; `404.astro` must exist, or Pages answers every unknown path
with the home page and a 200.

The build ends by linting the built HTML with [deadhead](https://deadhead.cevdet.ch/). A
harmful finding fails the build, and with it the Pages deployment; deprecated and unnecessary
findings are reported without failing it.

The site's own icons are generated by the current checked-out CLI from `src/icon.svg`,
using the explicit settings and manifest metadata in `favseed.config.mjs`. From the repo root:

```sh
pnpm --filter favseed-site icons
```

Run it after editing the source/config or upgrading Favseed or its encoders, then review and
commit the six generated files in `public/`. The site build copies those committed files;
it does not regenerate them. Edit manifest metadata in the config, since `site.webmanifest`
is generated. Padded PNGs share the opaque `#25170d` ground and safe-zone placement, declared
`any maskable`; the 48px ICO stays transparent. Animation and reduced-motion styling stay in
the SVG, shared by the favicon and header at `/icon.svg`.

Unchanged source, settings and engine versions reproduce the same files. A newer generator
may produce smaller or otherwise changed output; review those updates rather than preserving
old bytes across upgrades.

The Open Graph card is `src/og/og.svg`. Its lettering is outlined from Liberation Sans
Bold/Regular, so rendering needs no installed fonts. The comments label each text line;
when changing the wording, convert the replacement text to paths before saving the SVG.
From `site/`, regenerate the committed `public/og.png` with resvg, pngquant and oxipng:

```sh
resvg --skip-system-fonts src/og/og.svg /tmp/og.png
pngquant --force --speed 1 --nofs --colors 16 --output /tmp/og-q.png /tmp/og.png
oxipng -q -o max -s --zopfli -a --out public/og.png /tmp/og-q.png
```

Verified with resvg 0.49.0, pngquant 3.0.3 and oxipng 10.2.1. Identical source and tool
versions reproduce the same PNG locally; tool upgrades may change its bytes. Review the
regenerated card before committing it. The site build copies the committed PNG.

## One engine and identical output

The browser imports the same `lib/core.mjs`, `lib/config.mjs`, `lib/engine.mjs`, and
`lib/pipeline.mjs` as the CLI. The host adapters inject native or WASI
`@napi-rs/image` 1.15.0, the shared rebuilt Google Zopfli WASM, SVGO, and a deflate decoder.
Matching self-contained source and normalized options produce identical files, links, and placement.
The browser includes a manifest by default; the CLI needs `--manifest` to match.

Use self-contained SVGs for raster parity: outline text and embed images. The shared reference
pass warns about text/font and external-image dependencies without stripping them; native font
substitution and browser font availability can produce different raster pixels. Root dimensions
must provide a valid finite viewBox or positive absolute width/height. Browser `onWarn` callbacks
receive the same guidance as native `onWarn`, including cache replay; the form keeps warnings
separate from progress/errors and clears them on the next build. No resource fetching is added.

The Effort control matches `--effort`: Default (the form's default) keeps, for each raster,
the smallest encode that passes the accuracy bar and finishes it with Zopfli at 15
iterations; Fast makes one quality-80 encode with no Zopfli; Maximum tries every candidate
and runs Zopfli at 120 iterations. Quality and palette sit under "Advanced: pin a setting"
and are empty (Auto) by default, so nothing is pinned. A value pins that exact setting, as
`--quality` or `--colors` does: one encode, no search, and a warning when it misses the bar.
A quality below 100 cannot combine with a palette; the form disables and preserves the
palette field until quality is cleared or set to 100.

Full builds select SVG precision against minimally prepared source at 512px, allowing at most
1% bad pixels on either a black or white composite before PNG quantization. Passing marks keep
compact rounding; failed candidates retry higher precision, then retain source geometry if needed.
This checks the static base appearance, not every animation frame or display size. The
[current precision report](../bench/precision/README.md) records accuracy, byte/runtime effects
and the refreshed Vite PWA comparison. PNG quality does not disable SVG validation.

Wide and tall marks retain their proportions in square raster canvases. Raster preparation
centers the original rectangular SVG viewport, preserving percentage geometry and shifted
origins. Transparent outputs keep transparent bands; opaque PNGs use the chosen background
and existing safe-zone placement. The downloadable `icon.svg` keeps its original viewport.
See the [framing measurements](../bench/framing/README.md); square fixture output is unchanged.

Zopfli preserves pixels at every effort. One optimized `icon.svg` retains animation, styling and accessibility
and is reused by the site's header and favicon. Raster exports use a static base appearance.

Placement searches and raster outputs run in bounded batches, with serial fallback for large
custom sizes. When a fitted viewport exceeds twice the target size, placement probes render
centered on the target canvas. Moderate probes stay reusable across output sizes; no probe
canvas exceeds twice its target. The complete candidate walk and fitted geometry remain;
the bound applies per probe, not to probe count or process RAM. See the
[placement measurements](../bench/placement/README.md).
Builds run in a dedicated worker; Cancel terminates it and its children. Previous
successful downloads remain usable after a failed or cancelled build. One completed set is
cached in memory with owned copies and a 16 MiB budget; no source/result is persisted or uploaded.

At Default and Maximum effort with nothing pinned, the worker first builds the set Fast would
and posts it at once: the page shows it as the quick set, with its own downloads, while the
search goes on, then replaces it with the final set and says how the two compare. Downloads
always serve the best finished set and are labelled with which one it is; a quick set left by a
cancelled search stays, labelled as quick. The status line counts each encode of each raster's
search, and each file row shows the setting it kept, with its scores as a tooltip. Screen readers
are told the phases (building, quick set ready, done), not every step. Decision 30 in
[docs/DECISIONS.md](../docs/DECISIONS.md) records why, and
[bench/browser](../bench/browser/README.md) measures the time from choosing a file to the
engine being ready, the quick set and the final set.

After generation, **Copy markup** copies the displayed head links and announces success or
manual-copy guidance if clipboard access is denied. The code block stays selectable; browsers
without clipboard support show manual guidance. New results clear earlier copy feedback.

Zopfli finishing includes the guarded lossless palette pass described in the
[competitor measurements](../bench/zopfli/COMPETITOR.md). Those historical measurements predate
the effort control and single-SVG output change; [the default-performance
report](../bench/zopfli/DEFAULTS.md) records the later Zopfli-off measurements.

The ICO fallback has one 48×48 PNG entry. Generated links declare `sizes="48x48"`;
explicit 32px PNG requests stay 32px. Transparent 48px exports share the ICO payload,
while padded 48px PNGs remain separate. See the [ICO measurements](../bench/ico-size/README.md)
for the size and accuracy tradeoff; other file bytes are unchanged.

## Loading and hosting requirements

The image WASM asset is 10,322,976 bytes before transfer compression; production serves it
with Brotli (3,193,943 transferred bytes in the measured response). The loader starts with
64 MiB of growable shared memory. It preloads four async workers plus two to four spare workers,
and retains upstream fallback spawning. Loading starts on the first pointer, focus or drag
that reaches the drop zone, or when an SVG is chosen, never on page load; at Default and
Maximum effort the worker fetches the Zopfli WASM alongside the engine.
Earlier release-mode compressor and palette measurements are retained in `bench/zopfli/`;
they describe historical work, rather than the effort levels.

Use HTTPS (or localhost), WebAssembly and DecompressionStream. When shared memory is
available and transferable in both the page and worker, the browser uses the threaded engine.
Otherwise it automatically loads a single-thread compatibility build of the same image
engine. Privacy settings that disable shared memory no longer prevent generation. Only the
selected image engine is downloaded; a network or initialization error remains an error.
The build writes Cloudflare Pages `_headers` with COOP `same-origin`, COEP `require-corp`,
and CORP `same-origin` for documents and assets. Other hosts must supply equivalent response
headers, including worker responses, to retain the faster threaded path. Astro dev and preview
retain these isolation headers. Missing common APIs still get a clear CLI alternative.

`headers.mjs` also supplies `X-Content-Type-Options: nosniff`,
`Referrer-Policy: strict-origin-when-cross-origin`, and an enforced Content Security Policy
on documents and assets, including worker scripts. Production and preview permit same-origin
scripts/workers and WebAssembly compilation; inline JavaScript and JavaScript eval are blocked.
Inline CSS remains allowed for the inlined stylesheet and SVG styling. Local blob/data images
and blob download reads are allowed; external connections, object embeds, framing and native
form submissions are blocked. SVG previews remain image elements.

Only Astro dev allows inline scripts and WebSocket connections for its tooling and hot reload.
These allowances are excluded from the generated Cloudflare `_headers` and preview responses.
Vite keeps JavaScript chunks external even when they fall below its inlining threshold.
Other hosts must apply the security headers too; the local browser harnesses test the production
policy. After deployment, verify the actual document and worker response headers on Cloudflare.

`build/wasi-runtime.mjs` tunes the pinned threaded image1.15.0 loader's initial memory and spare
worker preload, and verifies the compatibility artifact hashes and image/runtime versions. It rejects changed package versions or loader defaults, retaining the memory
maximum, growth synchronization and cleanup. Both hosts load `lib/zopfli.wasm` through the same
adapter; the rebuild recipe and licenses live in `bench/zopfli/` and `lib/`.

The compatibility loader also starts at 64 MiB, with unshared growable memory and no child
workers. Its pinned rebuild recipe, provenance and benchmark are in
[bench/wasm-engine](../bench/wasm-engine/README.md); license notices ship at
`/engine-licenses.txt`. It reduced sampled renderer memory but generated more slowly in the
local investigation, so it is a fallback rather than the default.

On the local 16-core Chromium benchmark, this preload change reduces worker targets 21→9 and
renderer PSS after three fixtures 317–319→273–274 MiB, with equivalent build times. Warm
initialization measures 208 ms control versus 171–197 ms tuned. Run `node bench/browser-memory.mjs`
after building to reproduce it on Linux. The [native build comparison](../bench/zopfli/README.md)
measures 11–26% faster warm release builds with the rebuilt compressor and unchanged bytes.

## Verifying it

From the repository root:

```sh
pnpm --filter favseed-site test
pnpm --filter favseed-site build
node site/test/cdp-check.mjs
```

The harness serves `dist/` with the required headers and drives real Chromium through Node's
built-in DevTools WebSocket. It compares every file hash and shared metadata against native
builds over eleven effort-fast fixtures, two effort-max fixtures, and custom option cases.
It also checks ZIP contents, cache mutation/transfer ownership, page responsiveness, missing
isolation, cancellation, retry, nested-worker termination, and preservation of form downloads.
`/check` supplies the test API; fixtures and native references are supplied by the Node harness.
It deliberately stays in production so the deployed build can be diagnosed. Visiting it
only exposes that API; it starts no workers and downloads no WASM. Initialization and icon
generation require explicit API calls from a harness or developer. The existing browser suite guards settled startup
and explicit initialization; it does not detect arbitrarily delayed background work.
The page remains `noindex`, has no canonical URL and is excluded from the sitemap.

The browser command defaults to `chromium`; set `CHROME=google-chrome` to use Google Chrome.
Only these command names are accepted, and the browser must be on `PATH`.
`FAVSEED_SMOKE=1` runs a shorter matrix with all lifecycle checks.
`FAVSEED_BENCH=1` measures initialization, two effort-max and two effort-default fixtures.
To exercise an already-running dev or preview server, set
`FAVSEED_ORIGIN=http://127.0.0.1:4321` (only local HTTP origins are accepted).

### Other browsers and mobile emulation

The pinned Playwright suite runs desktop Chromium, Firefox and WebKit, plus Pixel 7 and
iPhone 13 emulation. It reuses native references, including small-coordinate and source-fallback
cases on desktop and mobile alongside gradient, maximum effort, transparent aliases and custom
manifest/animation options. It also checks cache ownership, ZIP downloads, page timers,
cancellation/retry, 1024px raster parity after shared or unshared memory growth, failure
preservation and touch controls at a 320 px viewport. Parity and lifecycle cases run in both
threaded and compatibility modes. Missing isolation or blocked sharing in a running realm selects compatibility. A host that
blocks worker startup still reports a startup error. With worker COEP missing under an
isolated document, Chromium and Firefox reject startup; WebKit starts a nonisolated worker
and selects compatibility. Load failures never silently switch engines. Both realms probe their own
capabilities, and the document can require compatibility even if its worker permits sharing.
`test/page.spec.mjs` checks homepage title/description, canonical/Open Graph/JSON-LD
consistency, the served 1200×630 share image, and noindex/no-canonical on `/check` and `/404`.
The documentation pages (`/how-it-works`, `/outputs`, `/benchmarks`) each get their own title,
description and slash-free canonical URL, and the sitemap lists those pages and the homepage only.
It also guards cold startup before any sign of intent, including form edits and a rejected PNG:
no workers or engine/WASM requests, at most 5 KiB gzipped HTML, 4 KiB gzipped JavaScript,
8 KiB combined HTML/JavaScript/CSS and 5 KiB raw inline/external CSS. Actual responses include
imports and preloads; each body is compressed separately with gzip level 9. Inline CSS is
already included in HTML for the combined budget. Images, headers and protocol overhead are
excluded; these are reproducible size comparisons, not Cloudflare transfer measurements or
load-time guarantees. The test attaches resource sizes and totals, then selects an SVG and
verifies that the engine loads and generation succeeds. The pre-selection observation ends
after settled network activity; it does not detect arbitrarily delayed background work.
Two further tests check that hovering over the drop zone starts the worker with the engine
and Zopfli WASM requests, and that focusing the file input starts it too.

Copy-control checks cover keyboard/touch activation, exact text, rejection/retry, missing API
and stale requests. Chromium projects also verify a real clipboard round trip with test-only
permissions; other projects control API responses to verify the UI independently of OS permissions.

After building, install the test browsers and run the suite:

```sh
pnpm --filter favseed-site exec playwright install --with-deps chromium firefox webkit
pnpm --filter favseed-site test:browser
pnpm --filter favseed-site test:browser --project=firefox
```

Browser downloads are separate from package installation. Use a Playwright-supported host;
`--with-deps` installs system dependencies on supported Linux distributions. CI runs each
project on Ubuntu 24.04, with one test worker and no automatic retries. Failed runs retain
traces and screenshots for three days.

WebKit testing does not establish compatibility with a particular released Safari version.
Mobile profiles emulate viewport, touch and device parameters on desktop engines. Real iOS
Safari and Android Chrome still need device checks, including memory pressure, the native file
picker and saving/opening the generated ZIP. Growable WASM memory and worker count still make
device verification relevant before release.
