# Changelog

All notable changes to this project are documented here. The format is
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

**Byte-output changes (a bumped `@napi-rs/image` or `@gfx/zopfli`, or any pipeline change) are
minor at minimum, never patch.** Downstream users diff these files into git.

## [Unreleased]

### Changed

- Measure maskable extents from each row's outermost visible pixels, avoiding interior
  scans while preserving placement and generated bytes. Reuse Astro's validated cache
  index during pruning and return owned Vite cache buffers without a second copy.
- Complete TypeScript declarations for existing root helpers and `favseed/core`,
  share image options across Node/Vite/Astro and document the advanced API boundaries.
  Cover packed NodeNext/Bundler consumers and imports without optional peers;
  runtime validation, dependencies and generated bytes are unchanged.
- Strengthen regression coverage for opt-in Zopfli, indexed and RGBA ICO payloads,
  48px ICO source/encoding accuracy, safe-zone sizes, SMIL event references and
  published package contents. Generated assets and runtime behavior are unchanged.
- Share validated persistent-cache reads between Vite and Astro so partial or malformed
  entries rebuild. Distinguish the default opaque background from explicit transparency
  in cache keys and invalidate older ambiguous entries.
- Include the installed SVGO version in engine/cache identity and preserve requested size
  order in cache keys so dependency updates and reordered manifests rebuild correctly.
- Validate custom Cargo homes in the browser compatibility rebuild script before I/O,
  applying the benchmark path boundary while retaining the standard Cargo home.
- Document the Node build APIs, upgrade workflow and troubleshooting in the README;
  declare the existing `buildFiles()` export and its in-memory result for TypeScript consumers.
- Keep `/check` available for deployed-site diagnostics and guard that visiting it starts
  no workers or WASM downloads until its API is explicitly initialized.
- Automatically use a pinned single-thread browser image engine when isolation or shared
  memory is unavailable, including privacy-hardened Firefox. Keep the faster threaded path
  where supported, lazy-load only the selected engine, and verify both modes against CLI bytes.

- Guard site metadata, startup HTML/JS/CSS budgets and deferred engine loading in the
  existing browser CI suite, including ordinary form edits and rejected non-SVG files.
- Enforce a site Content Security Policy with `nosniff` and a referrer policy, including
  worker responses. Preserve WASM, local previews/downloads and isolation headers; keep
  Astro development's inline-script/WebSocket allowances out of production and preview.
- Outline the site's Open Graph lettering so its SVG renders without installed fonts,
  and document font-free regeneration of the committed PNG.
- Add `pnpm --filter favseed-site icons` to rebuild the site's icons from a committed source
  SVG and config. Regenerate opaque, safe-zone-padded PNGs on the existing Apple ground,
  declare them `any maskable`, and retain site metadata, animation and the transparent 48px ICO.
- Add a browser copy button for generated head markup, with keyboard/touch access, polite
  success/failure feedback and manual guidance when clipboard access is unavailable. Keep
  previous downloads usable and ignore copy feedback from older generated results.
- Check reviewed fixture hashes, sizes and encoder/profile identity in platform CI, and
  reject patch releases that change them relative to the last stable release. Add an
  explicit baseline update command; generated image bytes are unchanged.
- Require the pinned development TypeScript compiler for config/Vite type checks, and test
  packed public imports with valid and invalid options under NodeNext and bundler resolution.
- Keep installed Astro middleware in Vite's transform pipeline so its virtual head-tag
  module resolves during dev, prerendering and Node SSR. Add packed-package integration
  coverage for static/dev/SSR behavior in a dedicated CI job.
- Validate Astro options before generation, including typos, unsupported `out`/`base` options
  and production values masked by fast development. Keep configuration paths lazy and use
  configuration property names in validation and renderer diagnostics.
- Serve Astro development icons from memory/cache without editing `public/` or its ownership
  record. Keep production publishing and owned legacy-file cleanup, and retain eight recently
  used verified cache sets while preserving older unverified slots, modified entries and symlinks.
- Defer SVGO initialization until SVG optimization, preserving the synchronous helper API.
  CLI help/version and early validation avoid loading it; Astro loads the Node build module
  only when building icons. Generated output and cache identity are unchanged.

### Fixed

- Report browser-check connection failures immediately with the active case and browser
  diagnostics, instead of hiding the original failure behind another protocol timeout.
- Correct the browser isolation check for WebKit: missing worker COEP selects the
  compatibility engine there, while Chromium and Firefox reject worker startup. Check
  native output parity on the successful path and threaded retry after restoring headers.

- Restore previous output after handled CLI/API publishing failures, including failures
  after earlier files were replaced. Preserve unrelated assets and symlink targets; retain
  recovery files if restoration fails and report cleanup errors alongside the original
  failure. Add subprocess late-write coverage. Generated image bytes are unchanged.
- Refresh Astro 7 incremental HTML when generated favicon links or automatic head injection
  change, while retaining eligible cached pages for unchanged head behavior and icon-only
  updates. Verify actual first installation through `astro add` from an independent project
  where Favseed is initially absent. Generated image bytes are unchanged.
- Reject missing CLI option values before a following recognized flag or `--`, while
  preserving inline literal values and dash-prefixed CSS assignments. Add a prefixed
  missing-input diagnostic and explain explicit padding with transparent output, including
  config-file options and quiet runs. Generated image bytes are unchanged.
- Export the Astro integration as the package-root default so `astro add favseed` writes
  a working config. Preserve existing named library exports and the CLI executable, and
  verify automatic installation with a packed-package build and repeat-install checks.
- Keep Astro HTML responses streaming after bounded head inspection instead of buffering
  the whole page. Detect existing icons only in the head, handle tags split across chunks,
  and pass through unchanged when a closing head is absent from the first 64 KiB.
- Reject malformed root viewBox number lists before source rendering or output writes,
  including missing values, hexadecimal numbers and repeated commas. Retain supported signed
  decimal/exponent notation and whitespace/comma separators. Bump to 0.8.0 for shared-pipeline
  cache invalidation; valid output bytes remain unchanged.
- Diagnose SVG text/font and external-image dependencies in the shared reference pass, and
  show the same guidance in CLI/API and browser, including cached browser builds. Preserve
  source content; outline text and embed images for consistent raster results across hosts.
  Reject unusable root dimensions with viewBox guidance before source rendering or writes.
  Bump to 0.7.0 for shared-pipeline cache invalidation; valid self-contained output bytes stay unchanged.
- Make Astro `head: true` an alias for automatic injection and include it in the public types.
  Report actual paths and ownership-recovery steps for asset conflicts, including starter
  favicon links and clean checkouts with missing ownership metadata. Existing files remain
  protected; generated image bytes are unchanged.
- Remove discontinued Astro-generated sizes, manifests and owned legacy SVGs from `public/`,
  including on cache hits and development-to-production transitions. Delete only unchanged
  regular files recorded as owned; preserve edited files, symlinks and unrelated assets.
  Keep the previous set intact when an incoming asset conflicts. Unstamped leftovers still
  require manual cleanup.
- Publish independent Astro asset copies so public edits cannot alter cached output and
  later be reclaimed and deleted. Bump to 0.5.1 to invalidate previously hardlinked caches;
  generated image bytes remain unchanged.

### Changed

- Bound placement-probe canvases to twice the target size, using target-size probes for
  searches above that threshold. Keep small marks enlarged into the safe zone, retain
  ordinary render reuse, the full candidate walk and existing selection/scheduling rules.
  Account for actual dimensions in the work estimate. Bump to 0.6.0 for integration caches.

- Use one 48×48 PNG-backed ICO fallback and matching link metadata across CLI, browser,
  Vite, Astro and the site. Keep explicit 32px PNGs and all non-ICO file bytes unchanged.
  Bump to 0.5.0 so integration caches regenerate the ICO.

- Preserve wide/tall logo proportions in square PNG/ICO output, including percentage geometry
  and shifted viewBox origins. Keep the exported SVG viewport and square-input bytes unchanged.
  Update the non-square warning and source-reference framing; retain existing safe-zone search,
  quality and opt-in compression. Bump to 0.4.0 for integration cache identity.

- Select SVG precision against the source's static 512px appearance with a 1% error budget.
  Keep compact precision 1 for passing marks; retry higher precision and retain unrounded
  source geometry if no candidate passes. Preserve animation/style/accessibility and use
  the same selector in browser and CLI. Reuse accepted pixels in the bounded placement cache.
  Correct gradient-stop rounding and small-viewBox geometry, and bump to 0.3.0 for cache identity.
  Refresh the Vite PWA comparison for corrected inputs; the old 2.9%-smaller claim no longer applies.

- Add PNG/ICO quality 1–100 across CLI, config/API, integrations and browser. Default 80
  balances size and fidelity; explicit 100 uses the higher-fidelity fixed-palette path. Custom colors without quality
  retain the fixed-palette path; explicit quality below 100 cannot combine with colors.
  Keep Zopfli independent and opt-in.

- Skip Zopfli by default; opt in with `--zopfli`, `zopfli: true`, or the browser's extra
  compression control. Release/fast effort remains 120/15 when enabled.
- Emit one optimized `icon.svg` preserving animation, styling and accessibility for both
  favicon and page use. Keep `--no-animation` as an explicit static option; retire `logo.svg`.
- Run complete alignment searches and raster outputs in bounded batches, with a canvas
  budget, serial fallback for large custom sizes, drained failures and owned native bytes.

- Try lossless Sub filtering before final compression for bare PNGs with full palettes,
  retaining the smaller preliminary encode. Both hosts share the change; 120/15 iterations
  remain unchanged. Bump to 0.2.0 so integration caches cannot reuse previous output bytes.
- Reduce browser image-engine initial shared memory from 250 to 64 MiB and cap spare worker
  preload at four, preserving memory growth, fallback spawning and cleanup.
- Rebuild the same Zopfli source with LLVM23 for the browser and CLI, retaining 120/15
  compression iterations and exact output bytes. Include the binary hash in engine/cache
  identity, ship licenses, and add reproducible build and performance scripts.
- Validate WASM requirements inside the image worker as well as the page, so missing worker
  isolation fails clearly even when a browser still exposes shared memory.
- Add CI browser parity and lifecycle checks for Firefox, WebKit and Chromium, with mobile
  Chrome/WebKit emulation and touch/download checks at 320 px.
- Correct browser instructions for selecting the CLI's fast mode through its config file.

- Browser and CLI now use the same pinned image engine, compression, shared options and build
  pipeline, with byte parity checked in Chromium. Browser builds run in a worker, support
  release/fast modes and cancellation, preserve previous downloads on failure, and cache one
  completed build. Placement renders are reused within a bounded per-build cache in both hosts.
- Browser hosting now supplies cross-origin isolation headers for shared WASM memory.
- Correct the ZIP writer's fixed DOS date to 1 January 1980.
- Keep generated download URLs alive when the browser preserves the page for Back/Forward
  navigation, and key cached manifests by the shared emitter's exact output.

- Rename the unpublished project to Favseed: package, CLI, configuration files,
  Astro/Vite imports and public API names. Existing local configurations must use
  `favseed.config.*`; no optimisation settings or icon formats change.

- Update repository and maintainer links to `cevdetch` and connect the package
  and website publisher to `https://cevdet.ch/`.

## [0.1.0] - 2026-10-01

### Added

- **A website**, <https://favseed.cevdet.ch> (`site/`): favseed in the browser, client-side,
  nothing uploaded. Astro, with a WASM raster stage (`@resvg/resvg-wasm`, `image-q`,
  `@jsquash/oxipng`) and a dependency-free zip writer. `logo.svg`, `icon.svg`,
  `site.webmanifest` and the safe-zone placement are byte-identical to the CLI's; the PNGs land
  within −6.1 % to +8.3 % of the CLI's at the defaults, and the page says so with the
  measurements rather than a disclaimer.
- **`lib/core.mjs`**, favseed's isomorphic half (the svgo stage, the ICO container, the mask
  maths, the manifest and the `<link>` block), imported by both the CLI and the website so the
  two cannot drift. Three seams make it portable: svgo is injected, the mask maths takes decoded
  pixels, and `icoWrap` works in `Uint8Array`. See decision 21.
- `site/test/cdp-check.mjs`: runs the real browser pipeline over four fixtures in headless
  Chromium, driven over the DevTools protocol with Node's built-in `WebSocket` and serving
  `dist/` from inside its own process. Checks PNG and ICO magic bytes, not byte counts alone.

- **One padded icon set, declared `"any maskable"`.** Every `--sizes` entry is placed in
  the W3C safe zone (a circle of radius 40 %) on `--bg`, the way the apple icon already was,
  so there is no separate `icon-maskable-512.png`: the set is both in truth, and Chrome will
  not install a PWA whose icons are all `maskable`. `--bg none` opts out in full:
  transparent, unpadded, `"any"` only. `icon.svg` is never listed in the manifest
  (crbug.com/40925759). On desktops, which do not mask, the icons show a smaller mark on
  their ground; that cost is stated rather than hidden (decision 22).
- The placement is measured by default and fixed on request: the farthest opaque pixel
  decides the scale at the icon's own size, and the scale then snaps down, within 10 %, to a
  size where the mark lands on whole pixels if that at least halves its anti-aliased pixels.
  That measurement is now the default of **`--padding`** (`auto`); a number overrides it with
  a fixed percentage per side, applied as given and never snapped. `build()` returns it as
  `fit: { apple, icons }`, and `placeInSafeZone()` is exported so the test suite's reference
  places the mark the same way.

- `favseed/astro`: an Astro integration. Builds in `astro:build:start` so Astro's ordinary
  `public/` copy carries the files to `outDir`: correct for static output and for every SSR
  adapter. Head tags via an `order: 'post'` middleware, a `<Head />` component, or logged for
  pasting.
- A content-addressed build cache for the integration, keyed on favseed's version, the input
  bytes, the canonicalised options **and** the versions of `@napi-rs/image` and `@gfx/zopfli`,
  so an engine upgrade invalidates it instead of serving stale bytes without notice.
- The integration refuses to overwrite a file in `public/` it did not write itself, checked by
  content rather than by filename. A file that already matches what it was about to write is
  left alone, so a clean install does not accuse you of hand-editing your own favicon.
- `build()`, `defineConfig()`, `optimiseSvg()`, `icoWrap()`, `engineVersions()` and
  `FavseedError` are exported, with types. `build()` throws; the CLI still exits.
- **A config file.** `favseed.config.js`, `.mjs` or `.ts` in the working directory sets any
  option, plus `input`, `base` and `mode`, which have no flag. Flags win; `--var` merges by
  name. `defineConfig` is exported from `favseed` with types. `base` reaches the `--html` links
  and the manifest's icon URLs, and the summary names the mode.
- **`favseed/vite`**, a Vite 8 plugin. Dev serves the set from memory in fast mode and rebuilds
  on change; a build emits the release set at the output root and links it in `index.html`;
  `virtual:favseed` exports the links and the files. It never shadows a different file in
  `public/`, shares the Astro integration's content-addressed cache, and leaves the manifest
  to vite-plugin-pwa when that is present, with `favseedIcons()` for its `manifest.icons`.
- `test/run.mjs`: the definition of done as `node:test`, with a PNG reader and an accuracy
  gate written over `node:zlib`. No bash, no ImageMagick.
- `bench/bench.mjs`: sweeps palette size, dither, stage order, zopfli iterations and the ICO
  container over `test/fixtures/`, and regenerates `docs/BENCHMARKS.md`.
- Twelve neutral fixtures, authored here. `heavy.svg` is generated by a committed script and
  calibrated to fail at `floatPrecision: 0` and pass at `1`.
- CI on Node 24: the whole suite on `ubuntu-24.04` (pinned), `macos-15` and `windows-latest`,
  a job that fails if the three disagree on a single output byte, a site build with a
  headless-browser check, and a lint of the workflows themselves.

### Changed

- **One engine, nothing to install.** `@napi-rs/image` renders, quantises and recompresses,
  and `@gfx/zopfli` (WASM) finishes the winner, both pinned to exact versions, so
  `npx favseed` needs Node 24 and no binaries. Renders are pixel-identical to `resvg -w N -h N`.
  Against the native resvg, pngquant and oxipng pipeline the PNGs are 3.6 % smaller over the
  fixtures (79 614 B against 82 605 B): 9.0 % smaller on the gradient, 0.46 % larger on the
  nine flat marks. Decision 26. The rasters stay one job at a time: parallel workers saved 13.5 %, short of the
  20 % bar (decision 27).

- **Node 24 or newer** (`engines: >=24`): CI tests one version, and 24 is both the floor
  and the current LTS.

- **`--colors` defaults to 256** (was 8). 8 colours missed the 1.0 % accuracy bar on
  anti-aliased marks and put 27 % of a gradient's pixels off by a visible margin; at 256 every
  non-gradient fixture is at least 8.8× inside the bar, for 44.6 % more bytes. 256 is a ceiling,
  not a target: a flat mark still uses only the colours it has. `--colors 8` restores the old
  trade. Decision 24.

- **`apple-touch-icon.png` now places the mark inside the safe zone.** It stays 180 px. iOS
  cuts the icon to a rounded square; unplaced, a mark with a 6 % margin lost 12 corner pixels to
  it. This changes the bytes of every `apple-touch-icon.png`, and the accuracy gate's reference
  for it is the placed source.
- **`--sizes` now defaults to `192 512`, was `256 512`.** web.dev's install criteria, Chrome's
  docs and MDN all ask for a 192 and a 512 `any` icon. This renames an output file:
  `icon-256.png` becomes `icon-192.png`.
- **`--bg` now defaults to `#000000`, was `#ffffff`.** iOS composites a transparent Home
  Screen icon onto black, so black is what the platform would have produced anyway; the
  default now says so instead of substituting white. A mark drawn on a light ground wants
  `--bg '#fff'`, and the warning when the flag is absent has always been there to ask.
- `svgo` is imported rather than spawned, and the plugins are plain objects. Removes a temp
  config directory, ~110 lines of stringified plugin source, an env-var channel and two Node
  startups. Output is byte-identical.
- Errors are prefixed `favseed:` (was `favicon.mjs:`).

### Fixed

- **The Astro integration no longer adds a second set of icon links** to a page that already
  links one with a `rel` such as `alternate icon`. It checked for a `rel` that starts with
  `icon`; favseed now looks for the `icon` keyword in any `<link>`'s `rel`, in the Astro
  middleware and in `favseed/vite` alike.

- **`<desc>` no longer reaches `icon.svg` or `logo.svg`.** svgo's `removeDesc` keeps any
  description that is not empty or an editor stamp, unless told otherwise; `general.svg`'s
  87-byte description was 30 % of its 289-byte `icon.svg`. The rasters are byte-identical.

- **A translucent `--bg` is refused.** The probe only checked that resvg parses the colour,
  so `transparent`, `rgba(…, 0)` and 8-digit hex passed, and the padded icons shipped with
  alpha while the manifest declared them maskable. favseed now reads the probe's pixel and
  fails with a pointer to `--bg none`.

- **A viewBox within 1 % of square is squared.** It used to be left alone, and resvg derived
  the second side: a 100×101 mark failed with "ICO payload is 32x33", and a 101×100 mark under
  `--bg none` wrote a 512×507 `icon-512.png` that the manifest declared 512×512. The
  non-square warning still fires only above 1 %, where the stretch shows.

- **The Astro integration puts `base` into the manifest.** Under `base: '/blog'` the page
  linked `/blog/site.webmanifest`, but the icons inside it pointed at `/icon-32.png` and
  404'd, so the PWA install failed. `base` now reaches the build and the cache key.

- **A `prefers-color-scheme` block survives into `icon.svg`.** svgo inlined the class it
  selects and then dropped the `@media` rule as unused, so a dark-mode favicon lost its dark
  rules without a warning. The rasters render the light rules as before (decision 25).

- **Non-square marks produced non-square rasters.** resvg does not stretch to fill `-w N -h N`:
  it preserves the aspect ratio and derives the second dimension, so a 128×64 mark came out
  32×16 and the ICO header disagreed with its own payload. `icon.svg` now carries a square
  intrinsic size and `preserveAspectRatio="none"`; `logo.svg` keeps its real proportions.
- **`icoWrap` validates its payload's IHDR** and refuses to write a header that disagrees with
  it, which is what turned the bug above from a wrong file that passed without a word into a
  failed build.
- **An animated mark could not be built at all.** svgo 4.1.0 crashes with
  `Unmatched selector: %` on `@keyframes` nested inside another at-rule, the very shape the
  animated-input contract requires. favseed hoists nested `@keyframes` to the top level of the
  same stylesheet, where svgo's parser already skips them as it should.
- **An animated `logo.svg` lost its animation without a warning.** `inlineStyles` deletes the
  `class` attribute it consumed without checking whether a media-guarded rule still selects it,
  and csso then drops the now-unused `@media` block. `inlineStyles` is switched off for the logo
  pass, and only for a mark where some name is selected by both an inlinable rule and a
  non-inlinable one. The common shape, with the motion class named only inside the guard, keeps
  the full inlining and the same bytes it has always had.

### Removed

- The `icotool` dependency. favseed writes the 22-byte ICO container itself, byte-identical to
  `icotool -c -r` on every fixture. `icoutils` is now only a test-time nicety.
- resvg, pngquant and oxipng as install requirements, with the `pngquant-bin` optional
  dependency, the `FAVSEED_RESVG`, `FAVSEED_PNGQUANT` and `FAVSEED_OXIPNG` overrides, and the
  `toolPath()` and `toolVersions()` exports. The native pipeline survives in `bench/` as the
  measured reference.
